# E840 rejection: StudyChat behaviour does not add longitudinal exam signal

The single frozen
`E840_studychat_longitudinal_assessment_transfer_v1` run executed from pushed
commit `6a78e0eba9d72f1ff7edce42445f9b1ebc880471` under project `.venv`
Python 3.12.8 and scikit-learn 1.8.0. Total runtime was `178.9796166`
seconds.

The target-free cross-source audit passed:

- all 20 behaviour features were nonconstant in both sources;
- 17/20 (`0.85`) competition feature medians were within `2.5` StudyChat IQR;
- 22,816 competition sessions had both student and tutor evidence.

The real external-outcome gate failed materially. Across 507 pre-exam samples
from 175 unseen-learner groups:

- prior-grade/usage baseline RMSE/MAE/Spearman:
  `0.1162921/0.0876747/0.4601022`;
- candidate with 20 dialogue behaviours:
  `0.1182231/0.0890782/0.4382660`;
- candidate gains:
  RMSE `-0.0019310`, MAE `-0.0014035`, Spearman `-0.0218362`;
- only `1/6` semester/exam cells improved RMSE;
- worst-cell RMSE gain was `-0.0037764`, within the safety bound but not a
  benefit;
- the 5,000-learner bootstrap observed/mean RMSE gain was
  `-0.0019310/-0.0019950`, 95% interval
  `[-0.0046666,0.0003241]`, support `0.0482`.

Six external materiality/stability clauses failed; only the worst-cell bound
and three target-free support/overlap clauses passed. StudyChat behaviour may
correlate with outcomes in pooled descriptive analyses, but it does not add
stable future-exam prediction after prior grades, usage, chronology, and
unseen-learner grouping are enforced.

Operational note: the command wrapper reached its 124-second ceiling while the
single `.venv` worker continued normally. Process inspection verified one
worker lineage, no duplicate was launched, and one foreground completion wait
was attached to that exact worker. It completed successfully; this was an
orchestration timeout, not a scientific rerun.
